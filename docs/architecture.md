# Architecture

## Product Shape

The product centers on a single entity: the tracked item.

Examples include company licences, insurance, contracts, employee documents, vehicle documents, software subscriptions, permits, and certificates.

The UI and API should optimize for:

- urgency
- responsibility
- renewal workflow
- history
- reminder delivery

## Application Layout

- Laravel serves the API, background jobs, policies, and file access controls.
- React + TypeScript + Vite renders the web UI.
- MySQL stores normalized business data.
- Redis handles queues, scheduled reminder jobs, and cache.
- Uploaded files are stored privately and are never directly public.

## Core Domain Decisions

1. Every business record is tenant-scoped.
2. Every protected request is checked server-side for authentication, tenant access, and permission.
3. Tracked items are distinct from documents. A tracked item may have one or more document versions.
4. Renewal history is append-only. Old expiry dates and old documents are preserved.
5. Status is derived from data where possible, with workflow exceptions handled explicitly.

## Authentication Choice

Use Laravel session auth for the browser app so CSRF protection and cookie-based session security remain straightforward.

If the app later needs third-party API access, add token auth in a separate layer without weakening the browser model.

## Tenant Isolation Strategy

Tenant isolation must exist in the database queries and authorization layer, not only in the UI.

Implementation rules:

- Every tenant-owned table has a `company_id` column.
- Policies and scopes always filter by the authenticated user’s allowed companies.
- Controllers never trust a `company_id` from the browser without validating membership.
- File access routes verify tenant ownership before download.

## Reminder Strategy

Reminders are generated by scheduled jobs from tracked item due dates and reminder rules.

Rules:

- reminders are idempotent
- reminders are logged
- reminder delivery is provider-agnostic
- email and in-app notifications are first-class channels

## Search Strategy

Search should be server-side and paginated.

Use indexed fields for:

- company_id
- status
- expiry_date
- responsible_user_id
- category_id
- branch_id

## Phase Boundaries

### Phase 1

Authentication, tenant setup, tracked items, categories, reminders, private uploads, audit logs, and dashboard.

### Phase 2

Bulk import, renewal workflow details, versioning improvements, branches, departments, reports, and email templates.

### Phase 3

WhatsApp, OCR, AI extraction, billing, advanced analytics, and integrations.
